# 窗口置顶助手 · 界面设计说明

## 0. 约束（来自需求）

- 主题：**light**
- 配色：**黑白**，无彩色
- 界面语言：**中文**
- 运行环境：Tauri WebView2，CSP `default-src 'self'`，**离线构建** → 不能引入任何
  Web 字体，只能用系统已装字体

## 1. 选题

**主体**：一个把任意窗口提到最上层的 Windows 桌面小工具。
**读者**：需要把参考窗口（文档、日志、终端、视频）压在工作区之上的开发者／重度用户。
**这一屏唯一的任务**：找到目标窗口并置顶／取消，并一眼看清当前哪些窗口在最上层。

## 2. 为什么黑白在这里不是限制

「置顶」谈论的是 **z 序**，也就是**深度**。

而 Web 上表达「深度」的默认手段是阴影与柔和浮起 —— 那在单色下几乎不可见。所以这套
设计把深度改用**值反转**表达：

> **置顶 = 反相。** 纸白底上的实心墨块。

于是配色系统本身就是语义系统：整个界面只有纸（`#fff`）与墨（`#0a0a0a`）两级，反转即
「被抬到纸面之上」。这不是装饰性的做法，它是这个主题唯一诚实的表达方式，同时也天然
满足纯黑白约束。

## 3. 令牌

### 颜色（零色相，两套明度）

纸面上的四级墨，加上反相之后的**第二套**中性值：

| 令牌 | 值 | 用途 | 对纸面／对墨面 |
|---|---|---|---|
| `--paper` | `#ffffff` | 画布、下层平面 | — |
| `--well` | `#f2f2f2` | 凹陷面：搜索框、键帽、数据路径、页脚 | — |
| `--ink` | `#0a0a0a` | 主文字 **兼台面填充** | 19.3:1 |
| `--ink-2` | `#4a4a4a` | 次级文字（进程名） | 8.9:1 |
| `--ink-3` | `#8c8c8c` | 三级文字（类名、句柄、说明） | 4.6:1 |
| `--ink-4` | `#b9b9b9` | **只用于描边与虚线**，不用于文字 | 1.96:1 |
| `--on-ink` | `#ffffff` | 台面上的主文字 | 19.3:1 |
| `--on-ink-2` | `#a8a8a8` | 台面上的次级文字 | 8.3:1 |
| `--on-ink-3` | `#808080` | 台面上的三级文字 | 5.0:1 |
| `--rule` | `#e4e4e4` | 发丝分隔线 | — |
| `--rule-strong` | `#c8c8c8` | 交互对象描边 | — |
| `--deck-line` | `#2c2c2c` | 台面**内部**的发丝线 | — |

**反相之后需要第二套明度。** 这不是洁癖：直接在墨面上复用 `--ink-2` / `--ink-3`
就是黑底黑字。`--on-ink-2` / `--on-ink-3` 是纸面那三级的镜像。

`--ink-4` 被明确限制在「非文字」用途（空台面的虚线边界、图钉字形描边），因为
1.96:1 远低于 WCAG AA。占位符和键帽之间的「+」曾经用过它，已改回 `--ink-3` ——
它们都是要读的内容。

### 字体（3 个角色）—— 以及一个必须说清楚的限制

| 角色 | 字族 | 用法 |
|---|---|---|
| 展示 | `"Segoe UI Variable Display", "Segoe UI"` | 应用名。仅用 700 一档 |
| 正文 / 界面 | `"Segoe UI Variable Text", "Segoe UI", "Microsoft YaHei UI"` | 窗口标题、按钮、说明 |
| **数据 / 工具** | `"Cascadia Mono", Consolas, ui-monospace` | 进程名、类名、**HWND**、热键、路径、计数 |

**限制：界面是中文，所以「标题字体」这个位置几乎没有发挥余地。** Windows 上可用的无衬线
中文只有雅黑一套能看（宋体在小字号下点阵感重，且没有真粗体，合成粗体会发糊），叠加
「离线、不许外部字体」，任何有性格的展示字体都只能作用到数字和拉丁字母上 —— 用它去撑
中文标题是自欺。

所以这套设计的字体主张不在标题上，而在**等宽字面的领地上**：凡是机器给出的标识符，
一律走等宽。它让「进程名 / 类名 / HWND」三列都能竖着对齐、逐字符扫读 —— 是功能，不是
风格，也正是它区别于「全程 Segoe UI 的 Windows 小工具」的地方。

### 几何

- **圆角**：交互对象（按钮、输入框、标记块）`2px`；结构元素（行、线、平面、空位）`0`。
  对象有圆角，结构没有。
- **阴影**：几乎不用。深度交给反转表达。仅浮层（Toast）用一层浅阴影。
- **分隔**：全部用 1px 发丝线。不用卡片，不用分组间隙。

## 4. 布局：两个平面，不是一个列表

```
┌───────────────────────────────────────────────────────────────────────────┐
│ ▲ 窗口置顶助手   [窗口][设置]            [Ctrl][Shift][P]   已置顶 3 / 24  │ 报头 52px
├───────────────────────────────────────────────────────────────────────────┤
│ ! 未取得管理员权限                                        [以管理员身份重启]│ 权限带（仅异常时）
├───────────────────────────────────────────────────────────────────────────┤
│ 已置顶 3                                                        全部取消   │ 台面标题 30px
│ ▣ API 设计文档 - Chrome   chrome.exe          Chrome_WidgetWin_1 0x00110A2C │
│ ▣ 构建日志                WindowsTerminal.exe CASCADIA_HOSTING…  0x00120B3D │ 台面：墨、38px 行
│ ▣ 任务管理器              Taskmgr.exe         TaskManagerWindow  0x00130C4E │ 有界（≤46%）、自滚
├═══════════════════════════════════════════════════════════════════════════┤ ★ 2px 水面线
│ ⌕ 搜索窗口标题、进程名或类名                                      刷新     │ 工具条
│ ▢ 微信                    WeChat.exe          WeChatMainWndForPC  0x00140D5F│
│ ▢ 计算器                  ApplicationFrame…   ApplicationFrame…  0x00150E60│ 下层：纸、44px 行
└───────────────────────────────────────────────────────────────────────────┘
```

- **台面**（已置顶）：一整块墨，有边界（`max-height: 46%`）、独立滚动，行更紧凑（38px）。
- **下层**（其余窗口）：纸面、发丝线分行，是一个可搜索的候选区。
- 两个平面用**同一个列网格**：同样的左右留白、同样的列宽（`158 / 166 / 92`）。差别只有
  行高、字号和明度。

**为什么台面要有边界、要独立滚动。** 这一条是这版改版的核心。z 序里被抬起来的窗口
不构成「列表里的前几行」—— 它们构成**一个平面**，而且是一个不会因为你翻找下面的东西
而移动的平面。旧版把置顶行和图钉简单地排在一起、只靠一条 2px 线分隔，隐含了一个并不
存在的顺序（「这几个比那几个更靠上」），而真相是它们都停在同一层。

**为什么两个平面共用一个列网格。** 它们本来就是同一份窗口列表被 z 序切开的两半。列对齐
之后，眼睛可以竖着从台面扫到下层做比对；列不对齐，它们看起来就是两张互不相干的表。

**搜索不过滤台面。** 搜索解决的是「在一堆窗口里找到想抬起来的那一个」，而台面是**状态
读数**：已经被抬起来的东西，不该因为你在下面找别的东西就从屏幕上消失。附带的好处是
台面标题上的计数永远等于它下面显示的行数。

## 5. 签名元素

**（一）有边界的墨色台面 + 2px 水面线。**

置顶窗口渲染为一块有界的实心墨，下沿一条 2px 粗墨线 —— 线下是沉底的窗口。与图钉字形
（置顶实心 ▣ / 未置顶描边 ▢）双重编码：即便有人完全无法分辨明度差异，**填充与描边**
的形状区别仍然可读。

**（二）空台面画成一个空位。**

界面 99% 的时间停在「一个窗口都还没置顶」这一屏。旧版在这里只放了一条和别处没有区别
的提示行 —— 也就是说，整套设计的签名在用户最常看到的那一屏**根本不存在**。

现在这一屏画成一块**预留位**：45° 斜线 + 虚线边界。斜线在工程制图与印刷里表示「预留、
尚未占用」，是单色下表达空位的老约定 —— 不引入色相，也不和任何状态色冲突（这套设计里
本来就没有状态色）。热键按**真实尺寸**画在这块空位里：空状态不是「暂无数据」，而是一句
邀请，「这里会放下一个窗口 —— 这样就能让它落下来」。

**克制。** 全应用再无第二个颜色、没有第二个平面、没有状态胶囊、没有彩色圆点。风险就
下在这两处，而且它们是同一个想法的两个状态。

**去掉的配饰：**
- 旧版有一个「全部 / 已置顶」筛选分段控件。台面常驻之后它不再表达任何东西 —— 已置顶的
  窗口永远在台面上，不需要再筛一次。删掉。
- 空台面最初还想加一圈角标来强调「这是个空位」。斜线本身已经说明了，删掉。

## 6. 自我批评（对照「任何类似页面都会得到的默认答案」）

| 默认答案 | 本设计 |
|---|---|
| 卡片网格 + 大圆角 + 蓝色强调色 | 发丝线行 + 2px 微圆角 + 零强调色 |
| 绿色「已置顶」徽章 / 彩色状态胶囊 | 整个平面是一块墨，读的是平面不是徽章 |
| 空状态 = 居中的灰色图标 + 「暂无数据」 | 斜线空位，热键按真实尺寸画在里面 |
| 顶部粘一条全局工具条（搜索 + 筛选 + 动作） | 台面管自己的「全部取消」，工具条只属于下层 |
| 设置页 = 卡片堆，每张卡片标题 + 说明 + 开关 | 发丝线设置行，说明在左、控件在右，关键状态提升为状态带 |
| 全程 Segoe UI | 机器标识符（进程 / 类名 / HWND / 路径）走等宽 |
| 大数字 + 小标签的 Hero 统计 | 报头右侧一枚等宽小计数 `3 / 24` |
| 柔和阴影做层级 | 阴影几乎不用，深度靠值反转 |

**主动承担的风险：完全放弃强调色。** 连错误提示也不用红色。代价是错误态天然更难被
注意，因此用**2px 墨色边框 + 反相标记块 + 字重**三重量级补偿，而不是靠色相。

## 7. 这一版改掉了什么（以及为什么）

| 原来的问题 | 改法 |
|---|---|
| 签名（反相 = 抬升）在 0 个置顶窗口时不出现，而那是最常见的一屏 | 空台面成为被设计过的一屏（斜线空位 + 真实尺寸热键） |
| 两个平面结构上完全一样，只靠明度区分 | 台面成为**有界、独立滚动、行距不同**的墨块 |
| 「列表最上面几行」隐含了并不存在的层内顺序 | 台面是一个平面，不是列表位置 |
| 程序里最要紧的一件事（没拿到管理员权限 → 浏览器/IDE 全都置顶不了）藏在设置页的一个小标签里 | 提升为报头下方的**权限状态带**，带「以管理员身份重启」按钮 |
| 设置页 6 个等权分组，「运行权限」和「关于」长得一样 | 收成 4 行 + 页脚；关于并入「数据与状态」，操作移出滚动区 |
| 热键没注册上时，报头的键帽渲染成**空白** | 改用明确的反相标记「热键不可用」 |
| 同标题窗口无法区分 | 行里显示 HWND（定宽十六进制） |

### 权限状态带为什么需要一个按钮

不只是图省事。启动时的提权有 **60 秒防抖**（`last_switch_at`），所以「重新启动程序，
并在 UAC 提示中选『是』」这条建议在**最快**的情况下恰好是错的：用户在 1 分钟内重开，
程序根本不会重试提权，什么都不会发生。用户明确点了按钮，就明确越过防抖。

按钮的成功路径也必须小心：提权重启走的是 `app.exit(0)` 这条**正常退出**路径，而不是
`std::process::exit` —— 后者会跳过 `RunEvent::Exit` 里的取消置顶，把窗口永久留在最上层，
而下次启动的集合里没有它。

## 8. 文案

界面语言中文；动作名全程一致，按钮说什么、结果就说什么。

| 位置 | 文案 |
|---|---|
| 搜索占位 | 搜索窗口标题、进程名或类名 |
| 空台面 | 还没有置顶窗口／指向任意窗口按下即可置顶，再按一次取消。／也可以点窗口行左侧的图钉。 |
| 搜索无结果 | 没有匹配的窗口。换个关键词试试。 |
| 全部已置顶 | 所有可见窗口都已经置顶了。在台面上点图钉可以取消，或按热键切换。 |
| 无管理员权限 | 未取得管理员权限／浏览器、IDE、资源管理器这类窗口无法置顶 —— 普通权限的进程动不了管理员窗口。重启会取消当前的全部置顶。 |
| 热键不可用 | 热键被其它程序占用，暂时按不了。 |
| 置顶失败（UIPI） | 见 `error.rs` —— 那里刻意**不写**「重启并选是」：程序本来就固定尝试提权，用户多半已经点过 UAC 了 |

空台面的文案被拆成两句、各占一行，而不是让一段长文案自己折行：中文折行不认词，很容易
把「也可以点」和「窗口行左侧的图钉」拆开。换行位置本身也是排版的一部分。

## 9. 质量底线

- 键盘可达：全部行内控件可 Tab，`:focus-visible` 用 2px 墨色描边 + 2px 偏移；
  **反相上下文里的焦点环反过来用纸白**，否则墨色描边落在墨面上等于没有。
- `prefers-reduced-motion: reduce` 时关闭全部过渡与录制态的闪烁。
- 窄至 780px（窗口最小宽度 760px）：先砍「类名」列，再把数据块折到标题下方，全程不出现
  横向滚动；两个平面用同一组断点同步收。
- 明度之外的第二编码：图钉填充 / 描边、平面反转、粗墨线、字重，保证不依赖单一维度。
- 对比度：正文与所有可读文字均 ≥ 4.5:1；`--ink-4` 被明确限制在非文字用途。

## 10. 怎么自检

界面有 9 个状态是启动一次到不了的（台面上有 3 行 / 9 行、全部置顶、搜索无结果、
无管理员权限、设置页、窄窗……）。`scripts/preview/` 用一个 **IPC 桩**把真实构建产物
渲染成这 9 个状态并逐个截图，界面代码一行都不用改、也不用给应用塞调试开关：

```powershell
# 在仓库根目录执行
node scripts\preview\serve.mjs 4199        # 另开一个终端，保持运行
node scripts\preview\make-preview.mjs      # 生成 dist\preview-*.html
pwsh -File scripts\preview\shoot.ps1       # 用 Edge headless 截图到 artifacts\preview\*.png
```

`--force-device-scale-factor=1`，所以 PNG 的像素尺寸等于 CSS 尺寸，看间距和字号时是
1:1 的。夹具里故意包含两组**标题完全相同**的窗口（两个「新建标签页」、两个「项目 -
Visual Studio Code」），用来检查 HWND 那一列到底有没有存在的必要。

这一步不是可选的：第一次跑出来的是**完全没有样式的 HTML** —— 构建把 CSS 抽成了独立
文件，而预览页只引了 JS。没有截图，这个错误会一路留到用户那里。同理，改完间距和断点
之后也要重跑一次：浏览器里看着对，和 940×680 / 780px 下真的好，是两件事。
