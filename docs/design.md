# 窗口置顶助手 · 界面设计说明

## 0. 约束（来自需求）

- 主题：**light**
- 配色：**黑白**，无彩色
- 运行环境：Tauri WebView2，CSP `default-src 'self'`，**离线构建** → 不能引入任何 Web 字体，只能用系统已装字体

## 1. 选题

**主体**：一个把任意窗口提到最上层的 Windows 桌面小工具。
**读者**：需要把参考窗口（文档、日志、终端、视频）压在工作区之上的开发者／重度用户。
**这一屏唯一的任务**：找到目标窗口并置顶／取消，并一眼看清当前哪些窗口在最上层。

## 2. 为什么黑白在这里不是限制

「置顶」谈论的是 **z 序**，也就是**深度**。

而 Web 上表达「深度」的默认手段是阴影与柔和浮起 —— 那在单色下几乎不可见。所以这套设计把深度改用**值反转**表达：

> **置顶 = 反相。** 纸白底上的实心墨块。

于是配色系统本身就是语义系统：整个界面只有纸（`#fff`）与墨（`#0a0a0a`）两级，反转即「被抬到纸面之上」。这不是装饰性的做法，它是这个主题唯一诚实的表达方式，同时也天然满足纯黑白约束。

## 3. 令牌

### 颜色（6 个中性值，零色相）

| 令牌 | 值 | 用途 |
|---|---|---|
| `--paper` | `#ffffff` | 画布 |
| `--well` | `#f4f4f4` | 凹陷面：搜索框、键帽、表头 |
| `--ink` | `#0a0a0a` | 主文字 **兼置顶行填充** |
| `--ink-2` | `#4a4a4a` | 次级文字 |
| `--ink-3` | `#8c8c8c` | 三级文字、禁用 |
| `--rule` | `#e3e3e3` | 发丝分隔线 |

对比度：`--ink` / `--paper` = 19.3:1；`--ink-2` / `--paper` = 8.9:1；`--ink-3` / `--paper` = 4.6:1。均达 WCAG AA。

### 字体（3 个角色）

| 角色 | 字族 | 用法 |
|---|---|---|
| 展示 | `"Segoe UI Variable Display", "Segoe UI", system-ui` | 应用名、分区标题。仅用 700 一档，负字距 `-0.02em`，克制使用 |
| 正文 / 界面 | `"Segoe UI Variable Text", "Segoe UI", "Microsoft YaHei UI"` | 窗口标题、按钮、说明 |
| **数据 / 工具** | `"Cascadia Mono", Consolas, "Microsoft YaHei UI", monospace` | 进程名、类名、HWND、热键、计数 |

**数据位用等宽是这套设计里唯一的字体主张。** 典型 Windows 工具会全程 Segoe UI；这里让机器标识符（`chrome.exe`、`Chrome_WidgetWin_1`、`0x000A1B2C`）走等宽，理由是它们本来就**是**机器数据，等宽让这一列可逐字符对齐、可扫读 —— 是真实功能，不是风格。

### 几何

- **圆角**：交互对象（按钮、输入框）`2px`；结构元素（行、分隔线）`0`。对象有圆角，结构没有。
- **阴影**：几乎不用。深度交给反转表达。仅浮层（错误条）用 1px 硬边 + 单层浅阴影。
- **分隔**：全部用 1px 发丝线，不用卡片间隙。

## 4. 布局（工作台，三带式，无侧栏）

```
┌───────────────────────────────────────────────────────────────────────┐
│ 窗口置顶助手          [窗口][设置]        [Ctrl][Alt][P]   3 / 42      │ 报头
├───────────────────────────────────────────────────────────────────────┤ 满幅发丝线
│ ⌕ 搜索窗口标题或进程名        全部 · 已置顶        ⟳ 刷新  全部取消   │ 工具条（安静）
├───────────────────────────────────────────────────────────────────────┤
│ ▣  API 设计文档                    chrome.exe          Chrome_Widget… │
│ ▣  构建日志                        WindowsTerminal.exe CASCADIA…      │
├───────────────────────────────────────────────────────────────────────┤
│ ▣  任务管理器                  ← 反相：实心墨底 + 纸白文字            │ ★ 已置顶
├═══════════════════════════════════════════════════════════════════════┤ ★ 2px 粗墨线
│ ▢  微信                            WeChat.exe          WeChatMainWn…  │
│ ▢  计算器                          ApplicationFrame…   Application…   │
└───────────────────────────────────────────────────────────────────────┘
```

- **报头**：应用名（紧、重）+ 视图切换 + **热键键帽** + 计数 `3 / 42`（等宽，小字；刻意不做成"大数字 Hero"）。
- **已置顶区与其余区之间用 2px 粗墨线**分隔，而不是靠颜色或留白 —— 这是「水面线」，线下是沉底的窗口。
- **列表**：发丝线分行，无卡片。置顶行整行反相。

## 5. 签名元素

**反相 = 抬升。**

置顶行渲染为实心墨块（`background: --ink`，文字 `--paper`），与图钉字形（置顶实心 ▣ / 未置顶描边 ▢）双重编码 —— 即便有人完全无法分辨明度差异，**填充与描边**的形状区别仍然可读。

克制：全应用**再无第二个颜色或状态装饰**。没有彩色徽章、没有状态胶囊、没有彩色圆点。风险就下在这一处。

## 6. 自我批评（对照「任何类似页面都会得到的默认答案」）

| 默认答案 | 本设计 |
|---|---|
| 卡片网格 + 大圆角 + 蓝色强调色 | 发丝线列表 + 2px 微圆角 + 零强调色 |
| 全程 Segoe UI | 机器标识符走 Cascadia Mono |
| 绿色「已置顶」徽章 / 彩色状态胶囊 | 整行反相 + 填充/描边字形 |
| 大数字 + 小标签的 Hero 统计 | 报头右侧一枚等宽小计数 `3 / 42` |
| 柔和阴影做层级 | 阴影几乎不用，深度靠值反转 |

**主动承担的风险：完全放弃强调色。** 连错误提示也不用红色。代价是错误态天然更难被注意，因此用**2px 墨色边框 + 反相标题带 + 字形**三重量级补偿，而不是靠色相。

**去掉的一件配饰**：原本给置顶行设计了左侧 3px 竖"stack rail"来强化抬升感，与整行反相叠加后信息重复 —— 已删除，只保留反相。

## 7. 文案

界面语言中文；动作名全程一致，按钮说什么、结果就说什么。

| 位置 | 文案 |
|---|---|
| 搜索占位 | 搜索窗口标题或进程名 |
| 空列表（未置顶任何窗口） | 还没有置顶窗口。指向一个窗口按 `Ctrl+Alt+P`，或在上方列表点图钉。 |
| 空搜索结果 | 没有匹配的窗口。换个关键词试试。 |
| 管理员窗口失败 | 无法置顶：目标窗口以管理员身份运行。以管理员身份重启本程序后可置顶。 |
| 热键注册失败 | 热键 `Ctrl+Alt+P` 被其他程序占用。界面仍可正常置顶。 |

## 8. 质量底线

- 键盘可达：全部行内控件可 Tab，`:focus-visible` 用 2px 墨色描边 + 2px 偏移。
- `prefers-reduced-motion: reduce` 时关闭全部过渡。
- 窄至 760px（窗口最小宽度）：等宽数据列折到第二行，不横向滚动。
- 明度之外的第二编码：图钉填充/描边、粗墨线、字重，保证不依赖单一维度。
